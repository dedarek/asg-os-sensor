# 三层接入与模型成本边界

系统只配置一个 Goose 模型，不自动切换昂贵模型。

## 1. 确定性接入

由现有扫描器收集当前进程与配置证据，检查命令 Hook、ACP 配置、OpenTelemetry 配置及已知扩展结构。协议结构只证明候选能力；加载、正文和阻断效果仍由当前实例的事件独立验证。未知插件接口交给模型学习，不按产品名称猜安装路径。

命令 Hook 和可包装的 ACP 启动配置复用现有通用执行器。OpenTelemetry 接收与归一化仅提供观测，不提供执行阻断。文件修改沿用实例检查、哈希前置条件、部署授权、备份与回滚。

协议证据检查可直接调用 `inspect_integration_protocols({})`：代码从当前调查选择最多 32 条成功的配置/入口/加载器/文件证据。显式传入混合编号时，格式错误、缺失、失败和非观察证据会被列入 `skipped_evidence`，其余证据继续检查；另一实例的证据直接拒绝。没有有效证据时明确报错，不能据此声称“不支持协议”。

## 2. 单一模型调查

未知构建先调查资产，再调查缺失的接入机制；这两个阶段使用同一个模型。页面模型设置决定下一次调查的模型。已有证据与部分发现落盘，可续查。

默认每次 Goose 运行最多 40 轮、重复工具调用限制为 3，分别由 `ASG_GOOSE_MAX_TURNS`、`ASG_GOOSE_MAX_TOOL_REPETITIONS` 覆盖。轮数不是工具调用数，也不是金额上限；一次模型轮次可能包含多次工具调用。达到限制仍未完成时保留结果，不标成功。现有重试冷却继续生效。

## 3. 配方沉淀与复用

兼容构建精确匹配后直接生成安装复用计划；新实例没有资产检查点不再自动触发一次模型调查。当前实例尚未采集的资产仍显示未知，不复制历史实例的运行成功状态。需要额外资产调查时可手动深度重测。

不兼容构建、复用执行失败、缺少复用验证材料、明确的验证失败或升级请求才进入模型调查。等待授权、等待重启或暂时没有活动均不单独触发模型。手动深度重测仍可重新调查。

精确匹配不是安装成功；配方文件、原始验证材料、安装记录和当前实例绑定继续由通用安装器检查。复制一行指纹不能替代完整可复用材料。

## 验收

- 同一真实兼容构建生成复用计划，`next_phase` 为 `None`，模型调用为零。
- 构建不匹配会进入调查；复用失败进入 Hook 调查；当前实例等待加载不借用旧实例成功。
- 历史混合证据失败调用可自动过滤后成功；跨实例证据仍被拒绝。
- 真实模型重测分别记录协议检查、候选配方、安装和活动结果；某一阶段成功不代表全链路通过。
