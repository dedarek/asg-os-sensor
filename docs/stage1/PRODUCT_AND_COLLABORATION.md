# Agent EDR MVP：产品与协作共识

记录日期：2026-09-10。此次记录不代表恢复开发。

## 已确认的产品方向
- 产品是面向 Agent 的终端检测与响应（EDR）MVP，Goose 是自主调查和适配引擎，不是产品本身。
- 尽快交付范围明确、实际可运行的版本，比一次实现全部能力更重要。阶段性汇报可用成果、真实证据、缺口和下一决策；不在单个问题上无限投入。
- 当前优先发现候选、辨别角色、自主调查身份与模型/MCP/Skill/规则资产，随后自主接入。高频监控、平台对接和阻断后续分阶段推进。
- 程序提供充分原始事实与通用工具，不把产品名、依赖或本地元数据当作最终角色结论；网关等基础设施不能默认当 Agent。
- 调查、资产理解、未知接入机制和版本变化更依赖 Goose；扫描、调度、身份绑定、持久化、授权执行、备份回滚、真实生效验证和高频运行依赖确定性程序。
- 第一次遇到靠 Goose 学，验证成功靠程序复用，变化时再调查。允许复用 Goose 自主学习且已验证的产品类别配方；禁止预写产品专用 adapter 再冒充自主学习。名称不是兼容条件。
- 不以固定短总时限强杀正常调查；记录原生限制并支持取消、保存和续查。不限制正常调查时间，不等于项目交付可以无限等待。
- 真模型调用、合成目标、真实 Agent、自主生成、人工干预、运行验证分别标注，测试数量不代替用户成果。

## 已确认的协作方向
- 执行者小步快跑：接一个小任务，尽快交回结果；顾问检查后再给下一步，避免一次下达复杂任务包导致多轮返工。
- 顾问负责方向、关键假设、独立验收和疑难根因，不能只转述执行者汇报；明确的小缺口由顾问直接补，不机械退回原执行者反复完善。
- 可以并行：执行者做实现和重复性验证时，顾问检查独立的风险、证据或接口，避免双方同时编辑同一区域。
- 对所有模型和自身判断保持证据驱动的审慎，不把完成声明当验收通过。

## 待确认的具体操作建议（不是已授权任务）
- 每张任务卡只包含一个可观察结果、允许修改范围、验收方式和返回点。
- 执行者先报告“改了什么、证据是什么、哪里不确定”，不为阶段回传反复制造大量文档。
- 顾问审查后决定接收、直接补小问题或安排下一项；同一问题反复出现时，由顾问接手定位，避免继续盲目返工。
- 并行前明确文件/模块所有权；接口先约定，集成与部署由一人协调。
- 阶段汇报节奏与模型调查运行时限分开。具体节奏在恢复前确认，不自行启动自动任务。

## 补充确认：当前是演示汇报用 PoC/MVP，不是生产上线
- 首要标准是核心链路在真实目标上验证成功，非测试数量、架构完善程度或生产级防护齐全。
- 先取得一个完整真实正例：无人工预置目标适配的真实 Agent，被发现、由 Goose 自主调查、建立指纹并生成接入方案、通过通用执行器挂接并取得实际验证证据；随后新实例兼容复用。已知品牌也可以，但其答案不能由开发者提前写好。
- 允许限定本机平台和验证范围、简陋界面、部分未知资产、未覆盖长尾；平台注册/阻断/生产级加固不是此次核心交付门槛。
- 不能用人工适配、合成目标、伪造事件或改成功标签替代上述核心验证。
- 用户可见交付应是一套可打开、可复现的演示：页面展示目标与角色、Goose工具活动、实际查得的关键资产及来源、学习得到的指纹/配方、安装与真实生效证据，以及第二次复用结果。资产缺失明确范围，不要求所有字段齐全才能形成正例。
- 配套一页演示说明：如何复现、哪些实际验证、哪些尚未支持。日志与测试作为证据附件而非成果主体。
- 中间汇报围绕链路节点和可见结果；一个节点阻塞时说明事实与选项，不无限完善外围工程、不把实施或调查长时间等待隐瞒为进展。
- 此为交付目标与范围记录，不是已经完成的声明、完成日期承诺，也不是用户授权恢复开发。仍等待用户明确开始。
