# Hook 验证台

部署后的页面提供“Hook 实时数据”：按实例查看实际事件和原始载荷，自动刷新并下载 JSON。缺失的数据类别会明确列出。参数或结果如果在旧 Hook 中已经被哈希或丢弃，页面无法还原，需要 Goose 重新学习并安装保留载荷的 Hook。

## 接入与验证

1. 发现进程、调查角色与资产。
2. Goose 读取实际扩展接口，生成带来源证据的文件计划；程序校验、备份、安装。
3. 安装后继续检查实例绑定和事件。需要重启的目标可在重启或新会话后加载；进程退出后历史事件不转移为新实例证明。
4. 观测源缺失或不可用时进入有上限的修复调查；等待用户实际操作本身不算失败。
5. 收到真实事件只证明相应类别已被捕获。工具前后事件配对不证明所有输入输出都被捕获。

## 执行控制

页面的 Hook 控制策略支持默认放行、拒绝或确认，以及按精确工具名配置规则。仅已安装同步控制回调的目标会查询这些策略。程序向 Goose 提供通用决策客户端协议，Goose 必须按目标真实接口实现暂停、拒绝和返回结果；不按产品名选择适配器。

确认请求会出现在页面，允许或拒绝只针对该次请求。超过等待时间会拒绝。控制模式中客户端错误或不可用必须拒绝，不能偷偷放行。策略接口返回决定和 Hook 回执均不是执行效果证明。

执行效果验收必须实际检查：放行的操作产生预期结果，拒绝的操作没有产生相应效果。测试脚本 `e2e/verify_control_delivery.py` 只驱动隔离测试 Agent 执行工具并检查文件，不创建 Hook、不直接调用回调、不伪造观测事件。

## 范围

- 文件事件来源保持观测能力；阻断能力由同步控制接口和目标回调共同实现，不能把所有来源统一标成支持阻断。
- 原始载荷会脱敏凭据，读取有窗口和条数上限，界面明确显示截取范围。
- 模型完整请求/响应、用户输入和助手输出是否可捕获取决于目标提供的接口；缺少证据时保持未接入。
- 测试用例与某一真实 Agent 验收成功都不等于所有 Agent 已通过验收。
