# 页面与采集真实延迟测量 2026-09-21

结论：**通过**。事件产生到页面 DOM 可见的浏览器真实测量首次完成：30 个真实样本，P95 2.73 秒（门槛 5 秒），最大 3.07 秒（门槛 10 秒），失败 0。G13 口径（P95≤3 秒、最大≤10 秒）同样满足。

## 测量方法

- 采集延迟（e2e/verify_latency_metrics.py --rounds 30）：向隔离 OpenCode 演示实例发送带唯一标记的真实回合，并行轮询 8081 的 /api/hook-data，延迟 = 页面可查时间 − 记录自带生产时间戳。30/30 样本有效，P95 0.457 秒，最大 0.654 秒。
- 页面可见延迟（e2e/verify_browser_latency_opencode.mjs）：headless Chrome 经 CDP 打开 8081 页面并点开 Hook 抽屉，发送唯一标记消息，等待标记出现在渲染后的抽屉 DOM 文本中；延迟 = DOM 可见时刻 − 记录生产时间戳。这是真实渲染可见性，不是刷新定时器配置值。
- 报告：artifacts/acceptance/browser-page-latency-opencode.json 与 latency-metrics.json，均含逐样本数值。

## 本轮发现并修复的测量缺陷

- 首次运行 30 样本全部超时。诊断：抽屉 2 秒周期重绘把已读记录留在 DOM 中，标记实际早已可见；失败原因是脚本假设 timestamp 是 ISO 字符串，实际为 epoch 秒数值，Date.parse 返回 NaN 导致永远判不可见。修复后 30/30 通过。教训已写入脚本注释：生产者时间戳两种格式都要解析。
- 测量结论只对本次运行的实例与包有效，不继承给其他通道或实例；跨通道继承正是 G13 点名要禁止的做法。
