# 通用调查：复用与本轮交付

## 未知进程发现补充

盲查发现 `dsh web` 的安装包入口可追溯，且进程实际打开多个 Skill 文档，但旧扫描器在缺少模型参数时直接给 0 分并丢弃，Goose 没有调查机会。缺陷发生在候选准入，不是 Goose 识别失败。

现在保留原行为分，另设候选准入通道：

| 证据族 | 当前入口 | 含义 |
| --- | --- | --- |
| 模型与服务参数 | model、provider、base-url 等参数名 | 可能使用模型服务 |
| 任务与指令参数 | prompt、task、instructions 等参数名 | 可能处理任务 |
| 工具与治理参数 | allowed-tools、approval-mode、mcp-config 等参数名 | 可能组织或控制工具 |
| 标准资产访问 | 当前打开 SKILL.md、AGENTS.md、MCP 配置候选文件 | 实际文件访问线索 |
| 工具子进程 | 直接派生 MCP 服务进程 | 可能是工具宿主 |
| 入口依赖声明 | 实际入口包的模型 SDK 依赖 | 声明能力，非运行证明 |
| 安装入口归属 | package bin 映射、桌面主程序与 bundle 声明一致 | 仅辅助定位，不能单独触发调查 |

这些信号只触发待确认调查，不将普通应用、编辑器或模型网关直接确认为 Agent。保留每族来源、采集失败和截断情况；不读取任务参数值。网络连接本身、普通浏览器子进程、提示文本中的产品名不作为肯定证据。已有 Hook 的模型/工具事件和 Goose 的角色调查承担后续验证。

当前仍是快照发现，不是完整时间序列画像。短暂文件访问、短命子进程、历史模型通信需要持续采集补充；不能把该版本说成覆盖所有行为。

## 可复用的基础

- 继续使用现有 psutil 采集进程与打开文件快照，不重新编写平台采集器。
- 继续使用现有 PyYAML safe_load 解析 Markdown 的名称、说明等元信息，并复用证据读取、脱敏和分页。
- [Agent Skills 规范](https://github.com/agentskills/agentskills/blob/main/docs/specification.mdx)可作为 SKILL.md 结构依据。本轮没有引入上游 skills-ref，也没有把格式解析称为加载验证。
- [AgentSight 安装说明](https://github.com/eunomia-bpf/agentsight/blob/master/docs/installation.md)区分 Linux eBPF 采集与便携会话文件读取；不能直接替代当前 macOS 上未知 Agent 的通用发现。
- [OpenLLMetry](https://github.com/traceloop/openllmetry)值得用于支持的 SDK 内部采集，但需要接入运行环境。本轮未安装或声称完成该接入。

## 已实现

原先目录按加入顺序截断为 12 项，而打开文件目录最后加入，真实线索可能被截掉。

现在保留采集范围内全部目录，合并同一路径的来源，按打开文件、声明配置目录、工作目录、入口和祖先路径等证据给出优先级。默认提供 Top 5；其余目录仍能搜索，过长的证据可沿用 read_evidence 分页读取。缓存、日志、依赖目录仅降权，不排除。排名不依赖产品名称。

文件采集返回 collected/unavailable、截断标记与错误类型，避免权限失败被误当作无文件。资产和 Hook 调查提示均要求继续追踪剩余线索，不能把 Top 5 当作完整性边界。

## 验证边界

新增任意命名的 16 个配置目录加一个真实打开的 Skill 文件用例，验证线索不丢失、元信息可解析、权限失败明确上报；另验证排名确定性和低优先级目录保留。对现有独立运行目标执行了只读快照验证。

这是当前打开文件快照的线索排序，不是历史文件访问次数 Top 5；短暂打开后关闭的文件仍可能缺失。真实文件访问历史需要另接持续事件采集器。本轮没有重新运行 Goose 全流程，不能把采集测试说成新 Agent 的完整接入验收。
