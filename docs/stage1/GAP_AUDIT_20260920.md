# ASG → SOC 全链路缺口复核（2026-09-20）

## 结论与范围

检查对象：ASG 当前工作树、SOC 网关与管理端源码、本地采集器 SQLite、SOC PostgreSQL、8081 实时状态，以及上一轮实看 8096 页面。按当前明确目标检查：ASG 负责发现/登记/选包/调查/安装，Hook 运行时直接访问 SOC；资产按用户最新要求手动采集；Windows 暂不验收。

结论：不能按“仅剩用户批准和外部机器”交付。合并重复问题后记录 **16 组 gap：10 组实现/集成问题、4 组验收或交付证据缺口、2 组外部环境验收**。这不是全仓库漏洞数量；没有将静态阅读扩张成完整运行证明，也没有本轮重测全部历史批次。

本轮未修改运行配置、未触发新的调查或安装、未替用户审批。集成测试重新执行 40/40 通过，但下面三项反例同样成立，说明现有测试不足以覆盖交付目标。

## 10 组实现与集成缺口

### G01 手动清点错误地阻止新实例发现、登记与离线重试【最高优先】

证据：endpoint.py 的 manual 分支没有 collection_requests 就 continue，discovery.refresh 和清单 flush 都在后面。现有 runtime 线程仅加载 enrolled，不能自动登记新实例。因此当前 Codex 不在已登记列表，旧 Codex 页面停住。离线请求的重试也会等下一次手动清点。

修复：生命周期发现/登记、缓存重发单独调度；手动开关只约束资产深度清点。页面“扫描”与“采集”使用清楚且一致的命令语义。按最新用户要求保留手动资产采集，不擅自恢复周期全量上传。

验收：manual 下启动新实例，30 秒内登记且标正确实例；不手动点击时全量资产采集次数为 0。断网创建新实例、退出进程后恢复网络，历史发现能补报且不伪装在线；100 条缓存缺失 0、逻辑重复 0。

### G02 自定义配置目录安装错位【最高优先】

证据：soc_onboarding.install_target 读取 CODEX_HOME/HERMES_HOME/OPENCLAW_STATE_DIR 后，只判断空值，有值仍返回 workspace。只读函数复现：CODEX_HOME=/tmp/custom-codex-home、workspace=/tmp，结果 /private/tmp。

修复：按协议对应的配置根安装；配置根、项目根、可执行文件位置各自传递。信任审计也必须使用该实例配置根，不能混入本机默认 ~/.codex。

验收：默认目录、自定义目录、带空格目录、两个并存实例各一例；修改只发生在预期根，错误目录写入 0，实例间信任/密钥串用 0。

### G03 信任审计把存在哈希等同于哈希有效【最高优先】

证据：codex_trust.audit 只检查 trusted_hash 非空；临时配置 deliberately-wrong 哈希可返回 trusted。解析器还固定 hook index=0，且逐行正则未完整覆盖 TOML 写法。

修复：优先读取目标权威准入结果；未能验证目标算法时只能报告“有信任记录，尚未验证有效”，不能猜 trusted。使用完整 TOML 解析；覆盖多 command、禁用、配置变更、实例独立 home。

验收：错误/旧哈希、禁用条目、配置修改均不得标已批准；正确批准后还需收到当前实例真实回调才标加载。保留目标原生审批，不伪造信任。

### G04 SOC 页面未呈现当前实例与明确准入动作【最高优先】

证据：8081 adapter.user_action 有 approval_required；asg-runtime-section.vue 只展示快照与折叠原始 JSON，没有专门的用户动作提示。SOC 旧 Codex 显示离线、审计模式、旧实例；不能说 SOC 已提示等待信任。

修复：展示当前/历史实例、状态来源、快照时间、准入动作；已安装、已加载、已观测、可阻断分别从实际证据计算。离线或旧实例不能给出当前可执行的误导按钮。

验收：未批准时一眼可见下一步；新实例不继承旧实例通过状态；服务端变更至页面可见 P95≤3 秒、最大≤10 秒，实际浏览器测量而非用刷新间隔代替。

### G05 原生包兼容校验没有真实约束输入【高优先】

证据：网关 asg_catalog.go 为原生包仅生成 adapter/agent_type。Python 虽支持平台/架构/版本/摘要字段，这些字段实际缺省。函数复现：不存在的 exe、unknown 版本仍可匹配这种原生目录条目。

修复：包携带可审核的兼容清单（支持协议版本、运行时范围、平台/架构、必要构建约束），网关保留并返回；未知兼容范围进入验证/调查。无需把所有包强制锁死单一构建，但必须有明确支持范围。

验收：兼容实例零模型选包；不兼容协议、版本、平台、摘要四组均拒绝自动安装。使用真实目录响应测试，不只测试人工补齐的 constraints。

### G06 installed 状态永久跳过安装与更新校验【高优先】

证据：discovery.py 见同 instance 结果 installed/already_installed 就 continue，不检查实际文件、当前包是否变化或加载是否失败。

修复：保存并比较选包版本、配置摘要、安装文件摘要；状态拆成安装回执与激活证据。相同内容不重复写；变更走升级计划与备份/回滚。

验收：同实例重复扫描 10 次写入次数 0；删除 Hook、篡改文件、发布更新包分别产生明确修复/升级状态；失败时恢复原文件，不能继续显示已接通。

### G07 无包 → 协议/Goose → 新包 → 安装的状态机未闭环【高优先】

证据：SQLite ZCode 是 needs_investigation、没有 investigation_requested。discovery.onboard(False) 会再次写入新结果，可能覆盖第一遍存下的 investigation_requested；refresh 内复用的 current 资产仍是调查前快照。

修复：持久化调查任务 ID 和生命周期，合并更新而非覆盖；调查完成重新读取结果；生成包、上传、选包、安装、验证逐步回执；不因无包反复开启相同调查。

验收：无兼容包真实目标走完整链路一次，重复扫描不重复调查；任务失败原因可见、续查保留进度；只有新实例回调完成才标接通。

### G08 直报事件的可靠性与执行回执不完整【最高优先】

证据：学习包安装器注入的 JS 队列在内存中，最多 500 条，溢出直接裁剪；重启丢队列；没有完整持久化重放。独立 soc_client 的 ack 仅返回本地 accepted，不送 SOC。直报事件部分路径缺 channel 字段。现有 ASG EventSpool 的 SQLite 补报不能证明停掉 ASG 后直报仍可靠。

修复：安装包内自带独立持久队列、稳定事件 ID、确认后推进游标、容量缺口显式记录；SOC 统一接收 decision/request_id/执行结果回执。统一 /api/analyze 与 /api/asg/events 两套记录的会话关联，避免重复计数。

验收：停 ASG，断 SOC 后产生至少 1000 事件并重启目标；恢复后缺失 0、逻辑重复 0，或明确逐条报告不支持范围；放行/拒绝/执行结果均可按同一调用查到。

### G09 非四类 Agent 的 MCP/资产调查结果未完整进入清点【高优先】

证据：discovery.confirmed 初始化 learned_mcp_configs=[]，仅从结构化 skills.value.items 取 path，没有相应 MCP 配置提取。collector.py 另有历史调查提取器，但 endpoint 当前用 protocol.collect_contract。

修复：统一一个结构化调查→清点映射；支持配置文件路径、字段定位、Skill 包根和 enabled 来源；来源缺失保持 unknown，不能猜品牌路径或补 0。

验收：一个非四类真实 Agent，调查查到的 Skill/MCP 逐项与 SOC 安装位置对账；添加/修改/删除/读取失败四种变化正确展示，失败保留旧数据。

### G10 8081 管理功能仍只是部分桥接【中优先】

证据：SOC 运行页模型设置只有 JSON 展示；后端操作白名单没有模型修改/连通验证。制品合并按钮依赖 merge_token，不能仅凭预览实现声称正式后端可用。页面控制策略走 8081 主机策略，与原生 Hook 请求 SOC 策略不等价。

修复：列迁移清单，每项指定唯一权威端。模型配置/测试、指纹配方查询、合并/撤销走正式鉴权 API；对原生直连 Agent 使用 SOC 策略编辑，不把本地策略成功当 SOC 生效。

验收：每项从 SOC 页面触发、终端/平台实际变化、回执可查；类型合并及撤销可恢复原归属；凭据不回显；真实无害文件操作验证策略影响。合并不按产品名自动执行，保留用户手动选择要求。

## 补齐顺序与交付口径

1. **先恢复一个用户可见真实闭环**：G01–G04，修实例登记/目录/信任/页面；用户审批后验证当前正常 Codex。结果是页面准确显示自己正在用的实例及必要动作，不再展示旧实例冒充当前。
2. **再完成安装器可靠性**：G05–G07；兼容包直接复用，变化重新检查，陌生入口只调查一次，调查完成自动产出可安装包。
