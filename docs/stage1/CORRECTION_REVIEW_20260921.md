# 纠偏记录与当前边界（2026-09-21）

本轮以一条产品主线为准：终端 ASG 发现 Agent；SOC 保存 Agent 类型和可部署 Hook 制品；终端先复用兼容制品，确无制品时先识别通用协议，协议不足才交给 Goose；安装后的 Hook 独立向 SOC 上报和请求决策。8081 只保留开发观察能力，不再是生产 Hook 的控制依赖。

## 已纠正的弯路

1. 删除了 `protocol_fastpath` 中直接修改目标配置、写本地事件日志、调用 8081 控制客户端的旧安装入口。协议扫描不再绕过 SOC 制品管理。
2. 取消“出现 Hook 关键词或配置形状就安装”。扫描现在区分：目标进程打开过配置、环境显式声明配置、相关目录约定文件。只有第一类加载证据可进入确定性制品生成。
3. 新的通用 command-Hook 包使用 `soc-direct-v1`，事件先持久化再发送；SOC 明确接受后才出队。控制回执不再把“返回了决定”伪装成“工具已实际执行”。
4. 解释器型 Agent 的复用同时校验解释器摘要和入口脚本摘要；只匹配 Python/Node 解释器不再算同一 Agent 构建。
5. 验收不再把历史实例、旧包和当前工作区混成一个结论。冻结报告保持原样，本文件记录其后的纠偏增量。

## 本轮新增的确定性链路

对满足以下全部条件的陌生 Agent，不调用模型：

1. 目标进程真实打开了一个 JSON 配置；
2. 配置在该实例工作目录内，且不是符号链接；
3. 配置包含可解析的 command-Hook 事件和现有 command 条目；
4. 可执行文件、入口内容、运行时、平台和架构均能生成明确摘要。

ASG 随后生成带完整文件内容、写前摘要、兼容约束、回滚信息和直报 SOC 运行时的制品，上传 SOC，再由正常制品目录下载和安装。失败、构建漂移或加载证据不足时不写文件，进入调查。

真实本机 SOC POC 验收见 `evidence/deterministic_protocol_soc_e2e_20260921.json`：制品上传、目录命中、安装、真实回调、用户原文事件送达、队列清空和事务回滚全部通过。

## 仍不能说完成的部分

- 确定性通用接入目前只覆盖“工作目录内、目标进程真实打开的 JSON command-Hook 配置”。JSONC/TOML 会被发现，但为避免破坏注释和格式，不自动改写。
- ACP 只完成发现、握手/流记录和权限语义实验，尚未形成可由 SOC 部署的通用安装包，因此继续进入调查。
- 本轮真实 SOC 测试使用隔离协议宿主，尚未代替一个全新第三方 Agent 的独立重启、10 回合输入输出、工具放行/拒绝验收。
- 生成包后仍必须等待目标新实例回调；“SOC 已登记/已安装”不等于“已激活/已阻断”。
- 0.9.6 已绑定提交 `43b3f0b` 和 manifest `1b10895d...`，17/17 终端生命周期通过，现为本轮确定交付版本；其结论仍不替代真实第三方 Agent 的独立激活与阻断验收。
